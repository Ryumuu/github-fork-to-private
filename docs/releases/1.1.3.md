# 1.1.3 — 识别导入进度页 500 报错并后台检测完成 / Handle GitHub /import 500 progress page

## 中文

- 当源仓库包含大量分支、标签或历史 PR 引用（如上千个 `refs/pull/*`）时，GitHub 提交导入后跳转的 `/<账号>/<仓库>/import` 进度展示页可能直接返回 `500 Looks like something went wrong!`，但 GitHub 后台通常仍在继续复制代码。
- 1.1.3 在已发起提交的同一标签页跳转到 `/<账号>/<仓库>/import` 且遇到 GitHub `500` 页面时，会在页面顶部显示「已发起私有复制 · 源仓库分支和 PR 记录太多，请耐心等待」横幅与目标仓库直达按钮，提醒不要重复点击。
- 横幅在后台每 5 秒检测目标仓库页面；仅当核对目标仓库为私有（`octolytics-dimension-repository_public="false"`）且代码文件视图已就绪（`route-controller="files"`）后，才更新为「已复制成功！源仓库分支和 PR 记录太多，后台已完成导入」。
- 排除 `/<账号>/<仓库>/import` 页面上的仓库复制按钮注入与弹窗源仓库识别，防止在进度页误点产生嵌套复制。
- 91 项自动化回归测试全部通过；不新增权限或外部依赖。

更新后，请在 `chrome://extensions` 点击「重新加载」并确认版本为 **1.1.3**。

## English

- When a source repository has many branches, tags, or historical pull-request refs (such as over a thousand `refs/pull/*` refs), GitHub's redirected `/<owner>/<repo>/import` progress page may return `500 Looks like something went wrong!` while GitHub's backend continues importing the repository in the background.
- In 1.1.3, when the tab for a submitted import task lands on `/<owner>/<repo>/import` and encounters GitHub's `500` page, the extension displays a top banner explaining that the copy was submitted and has many branch/PR records so you should wait patiently without clicking again, along with a direct link to the target repository.
- The banner polls the target repository page every 5 seconds and updates to confirm completion only after verifying that the repository is private (`octolytics-dimension-repository_public="false"`) and its files view is ready (`route-controller="files"`).
- Excludes `/<owner>/<repo>/import` from repository button injection and popup source-repository detection.
- All 91 automated regression tests pass; no new permissions or dependencies.

After updating, click **Reload** at `chrome://extensions` and confirm version **1.1.3**.
